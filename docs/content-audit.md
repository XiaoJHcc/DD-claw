# 分类与推送记录

图文页每条近期帖子右侧的记录按钮、时间表中的直播条，都可打开「分类与推送记录」。入口共用组件，数据按直播场次或平台帖子身份键保存，重启后仍可查看。

## 记录内容

- 分类：当时的内容文本与标签、分类标准快照、每项属于/不属于的结论、来源、置信度、依据、视觉输入张数和耗时。直播与图文的确定性负判也可回看，不改变旧 verdicts 的归档语义。
- 模型：各 provider 的名称、模型、成功/失败/跳过状态及错误；LLM 关闭、没有 provider、调用或解析失败时，记录确定性回退原因。模型漏返或重复分类、置信度不在 0–1 范围内均拒绝采纳，按既有 provider 降级及确定性回退处理。
- 推送：当时的规则快照、未命中原因、所选渠道及启停状态、最终推送词、通道/目标发送结果。成功、部分成功、失败、演练与未推送分别展示。图片下载不完整、翻译失败也展示降级说明。

分类「属于」不代表已推送；分类「不属于」也不代表未推送，任意内容规则仍可命中。发送成功指通知通道返回成功，不是收件人已读。

## 数据与能力面

`content_audit` 按 `(subject_type, subject_id)` 保存最新一次分析和推送过程，两段独立更新。归档不进入配置撤销栈。分类标准和规则快照随当次过程保存，修改配置不重写历史；不保存密钥或图片 base64。

admin 工具 `get_content_audit({subjectType, subjectId})` 返回 `{audit, verdicts}`；`GET /api/content-audit` 经同一工具执行。gateway 不暴露本工具。身份键：直播 `roomId:liveTime`，图文 `platform:itemId`。demo 提供成功、失败和无记录示例。

## 已知边界

- 记录从升级后的新处理开始产生，不反推旧内容的发送状态。旧分类结果仍可回看。
- source 恢复轮静默归档的帖子没有 `feed_post`，不会产生推送过程；界面明确显示未记录，不将其解释为分类判否。
- 抓取网络失败发生在内容信号产生之前，仍在来源状态、账号故障标记与运行日志中查看；本记录覆盖模型调用、图片降级、翻译和通知发送。
- 每份内容保存最新过程，尚不提供多次重判对比、跨内容总览或保留期清理。

## 合并升级

旧 MCP `upsert_push_rule.uids` 会明确拒绝保存，调用方改为 `scope` 后重试，避免旧字段被剥离而变成全部主播。旧图文 filters 迁移后是确定性回退条件；有提示词且 LLM 可用时以提示词为准，需要将仍然要求的原创/带图等限制写进分类提示词。

发布前备份 SQLite（停服务后备份，或使用 SQLite 一致性备份）；旧 post_rules/账号 rule_ids 等迁移不可通过配置撤销恢复。回退旧代码时需要恢复相匹配的数据库。
