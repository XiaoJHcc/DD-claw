# 分类与推送记录

图文页每条近期帖子右侧的记录按钮、时间表中的直播条，都可打开「分类与推送记录」。入口共用组件，数据按直播场次或平台帖子身份键保存，重启后仍可查看。

## 记录内容

- 分类：当时的内容文本与标签、分类标准快照、视觉输入张数、未送模型的图片及原因、耗时。结论按分类分组：每个分类恰有一条生效结论（属于/不属于、来源、依据；决策模型另有概率），同一分类其他来源跑出的结论作为次要行一并保留。精确模式（逐条原子条件）的分类另记逐条件结果：条件 id、原文、方向、P(成立)、灰区分带及是否实际促成定案——不合成一个伪最终概率，是非只看裁决结果。
- 主分类：生效的主分类（「其他」表示组内都不像）与来源；决策模型给出各项概率分布；其他来源的主分类结论作为次要行。
- 模型：各通道（LLM / 决策）各 provider 的名称、模型、成功/失败/跳过状态及错误；某档被跳过或失败另有单独的原因记录（决策档：总开关关 / 无供应商 / 全部候选失败），LLM 档的不可用原因另记一条。模型漏返或重复分类、主分类不在选项集内均拒绝采纳，按既有 provider 降级及确定性回退处理。
- 推送：当时的规则快照、未命中原因、所选渠道及启停状态、最终推送词、通道/目标发送结果。成功、部分成功、失败、演练与未推送分别展示。图片下载不完整、翻译失败也展示降级说明。
- 判定未执行：整轮判定被跳过时（例如只启用了 LLM 档、该房间还在冷却），判定侧记「未执行」（不是失败），当前分类结论与时间表的历史都不变；推送侧另记一条跳过原因。两者不共用同一句文案。

分类「属于」不代表已推送；分类「不属于」也不代表未推送，任意内容规则仍可命中。发送成功指通知通道返回成功，不是收件人已读。

## 数据与能力面

`content_audit` 按 `(subject_type, subject_id)` 保存最新一次分析和推送过程，两段独立更新。归档不进入配置撤销栈。分类标准和规则快照随当次过程保存，修改配置不重写历史；不保存密钥或图片 base64。

admin 工具 `get_content_audit({subjectType, subjectId})` 返回 `{audit, verdicts, primary}`（后两者为全部来源行，带 `effective`）；`GET /api/content-audit` 经同一工具执行。gateway 不暴露本工具。身份键：直播 `roomId:liveTime`，图文 `platform:itemId`。demo 提供成功、失败和无记录示例。

## 已知边界

- 记录从该功能上线后的新处理开始产生，不反推旧内容的发送状态。旧分类结果仍可回看。
- source 恢复轮静默归档的帖子没有 `feed_post`，不会产生推送过程；界面明确显示未记录，不将其解释为分类判否。
- 抓取网络失败发生在内容信号产生之前，仍在来源状态、账号故障标记与运行日志中查看；本记录覆盖模型调用、图片降级、翻译和通知发送。
- 每份内容保存最新过程，尚不提供多次重判对比、跨内容总览或保留期清理。
- 逐来源落库之前的旧 `verdicts` 行一律视为生效；当时直播侧只记正判，所以旧直播场次没有判否行，不能据此显示成「不属于」。

## 升级与回退

迁移机制（在线补列 / 带闸门的一次性搬家、顺序、幂等与备份还原）见 [modules/core.md](modules/core.md)「Schema 演进与一次性迁移」；本节只留与本记录相关的两条：

- **归档不随升级重写**：保存的是当时的分类标准与命中规则，配置改动不改历史；旧库判定身份键由启动期迁移重建。
- **先备份、回退要配对**：一次性迁移不进撤销栈、不可通过配置撤销恢复；回退旧代码时需恢复与之 schema 匹配的库。

旧字段（如 `upsert_push_rule.uids`）会被明确拒绝而不是静默剥离，见 [mcp.md](mcp.md)；旧图文规则如何拆成分类与规则见 [统一计划附录 A](plan/unify-classify-push.md)（历史执行规格）。
