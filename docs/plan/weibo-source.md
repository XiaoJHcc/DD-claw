# 微博图文来源实施计划（与 X 同构）

> **状态**：已落地。前置：X/推特 P0–P3 已落地（[twitter-source.md](twitter-source.md)）——本计划把微博从「主播的附属数据源」
> 升级为**与之平行的第二条独立图文来源**。一句话：**微博与 X 走同一条图文链路**（独立名单 → 源 → `feed_post` → 分类与推送规则），
> 差别只剩「微博要登录态、X 要代理」。细则以源码与本目录其它文档为准；本文保留决策依据、迁移语义与验收条款。

## 起点（为什么要做）

| | 迁前 | 迁后 |
|---|---|---|
| 名单 | `streamers.weibo_uid`（**附属**：只有 B站主播能绑微博） | `weibo_accounts`（**独立**：独立博主也能加；关联主播只是可选字段） |
| 帖子归属 | `posts.uid` = **B站 uid**（供主播卡第三栏混排） | `posts.uid` = **微博账号 uid**（与 X 存 screen name 同语义；第三栏改由关联反查） |
| 推送 | `feed_post` 被 pipeline **显式跳过**（只认 X） | 与 X 同一分支：分类判定 → 推送规则 → 推送（微博图境内直连下载后交 NapCat） |
| 规则 | 旧图文规则的账号集合只指 X 名单 | 曾是「规则带 `platform` 分流」，后并入统一模型：分类用 `applies_to=post`，规则用 `subject_kind` + 平台前缀 scope（`twitter:` / `weibo:` / `bili:`），见 [统一计划](unify-classify-push.md) |
| 面板 | 微博只有一行登录态 + 抓取间隔 | 与 X 同构的账号卡片墙，图文页单墙混排 + 平台筛选胶囊 |

## 已定决策

1. **独立表 `weibo_accounts`**（镜像 X 名单）：uid / 昵称 / 可选关联主播 / 启停 / 增量游标 / 最近成功抓取 / 头像 / 时间戳。
2. **帖子归属改按微博账号 uid**，**主播卡第三栏经「关联主播」反查继续混排**（对用户透明），老库一次性迁移。
3. **图文页单墙混排 + 平台筛选胶囊**（全部 / X / 微博 / B站动态）：卡片带平台角标——规则与分类按内容类型分流，用户必须一眼看出配置落在哪。

## 数据模型与一次性迁移

- `weibo_accounts`：`uid` 唯一（数字 uid，收 `2203177060` / `u/…` / `weibo.com/u/…` 三种写法并归一）、可空昵称、可空关联主播、启停、增量游标（只往前推，按数值比较）、最近成功抓取（区分「抓过」与「从没成功」）、本地头像文件名。
- **一次性数据搬家**（settings 闸门，幂等）：① `streamers.weibo_uid` → `weibo_accounts`（昵称照抄、关联回指原主播、启停随监听状态）；② 历史微博帖的 `posts.uid` 从 B站 uid 改写为微博 uid（B站动态不受影响）。
- 为什么用闸门而不是条件判断：改写后 `posts.uid` 已是微博 uid、与原关联字段不再相等，重跑本就是空操作——闸门只是让「只跑一次」显式可读。
- 旧图文规则表的 `platform` 列已随统一计划消失；现行规则用**平台前缀的账号引用**表达范围，两条名单的自增 id 相撞不再有歧义。

## 落地要点

| 层 | 要点 |

| 推送分支 | 两平台共用：账号在各自名单查、分类按内容类型判、规则按 scope 引用匹配；图：X 走代理隧道 / 微博图床境内直连 |

| 面板 | `/api/weibo/accounts` CRUD + 头像端点；规则校验按平台查名单；主播详情填微博昵称时联动建/关联名单行（面板与 MCP 共用） |
| 装配 | 微博源的运行前提是登录态，**名单为空不启动**；间隔/名单指纹变化就地重启；状态快照给面板 |

## 实现中确认/修正的点

1. **微博没有「引用」这种形态**：转发在抓取层就折进 `type='retweet'`（正文拼 `//转发自 @原作者`），没有像 X `quoted_tweet` 那样的独立实体。所以分类的「引用」条件对微博帖永不命中（是语义而非校验错误），翻译作为规则附加动作运行时也跳过微博——界面在对应控件上标注「仅 X」，不摆一个永远不生效的开关。
2. **账号引用必须带平台前缀**：X 与微博（以及 B站动态）名单各自自增 id，靠 id 无法跨平台定位；scope 用 `twitter:screenName` / `weibo:uid` / `bili:uid`，换主体时引用本身不会指错平台。
3. **微博头像用直连下载**（`sinaimg.cn` 境内可达），不走 X 那条代理隧道；字段优先 `avatar_large`。头像 URL 带签名与过期参数（同一头像每轮 URL 也可能不同），所以按 URL 的 md5 落盘、且只在还没有本地头像时下载一次。帖子图复用图片本地化时按域带 weibo Referer（防盗链，见 [boundaries.md](../boundaries.md) §5.38）。
4. **状态快照是「抓不到 vs 没新帖」可区分的前提**：由源每轮回写，`GET /api/weibo` 只读快照、绝不打网络。**面板微博卡保持登录态一行**，不展示这份快照——它是可观测证据与后续扩展点。
5. **名单为空不启动**（与 X 同一条判据）：否则面板会显示「运行中」却什么都不抓。
6. **`posts.uid` 语义变更的连带**：主播卡第三栏的反查是唯一读取点，其余查询都按 `platform + uid` 精确取。
7. **不加「填 uid 就验证账号存在」**：X 有便宜的免登录存在性接口，微博没有等价的匿名接口——硬加等于把添加流程挂在一个未实测的端点上。填昵称时走匿名解析链（解析不到即 400），只填 uid 时不校验，抓取失败由账号级告警兜住（见 [boundaries.md](../boundaries.md) §5.37）。

## 边界 / 未做

- **不写微博**（不转发、不点赞、不关注）；只读。
- **微博关注列表不同步**（仍以 B站关注为候选池；[design](../design.md) §10 的待定项不变）。
- 微博帖**不做引用筛选**、**不做翻译**（见上 §1）。

## 验收条款

1. `npm run typecheck && npm test && npm run build` 全绿。
2. `?demo=1` 浏览器实测：单墙混排（含一个未关联主播的独立博主）、筛选胶囊计数、平台角标、微博账号浮窗（uid 只读 + 昵称 + 关联主播 + 生效规则）、规则与分类的平台边界提示、增删改与就地报错（重名 / 昵称找不到）；**微博卡与改动前一致**（只有登录态一行）。
3. 迁移在 `db.test.ts` 里用「旧 schema 库」端到端验证：种子 + 归属改写 + 二次打开幂等。
4. **开播路径零回归**：设置页、时间表、主播列表行为不变（第三栏混排由关联反查保持）。
