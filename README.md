# DD-claw

B 站主播开播动态监听、分类、推送工具：

盯住你在意的 B 站主播（直播间、动态、微博），自动判断每场直播「是什么内容」，再按你定的规则把消息推到 QQ（NapCat）或系统通知。

附赠 X（推特）、微博、B 站动态的图文监听，不仅能推 V 还能推 nsy。

## 核心设计

### 抓取

抓取内容全部留档，供分析模块进行判断。

- **直播间**：监听开播/下播信号、标题、分区、封面图、关键帧，用于分析直播内容。
- **动态**：监听新动态（含图片），用于分析直播预告、周表。
- **微博**：监听微博和评论，用于分析直播推迟、临时通知等。
- **X（推特）**：监听 X 的推文，可以单独走图文规则推送。


### 分析

分析结果追加入库，由推送模块决定取用。

- **直播分类**：每场直播自动归类——歌回、3D、生日、晚八聊聊……
    - 规则判断：标题/分区**关键词匹配**，直接确定分类。
    - LLM 判断：用**自然语言描述规则**（可配多模态模型看直播画面）。（正在开发）

- **直播预告**：从动态/微博抓取的直播预告、周表，通过 LLM 分析**自动填写直播时间表**。（画饼，待开发）

- **图文分析**：从X/微博抓取的图文推文，通过 LLM 分析**筛选是否推送**，顺便可选**翻译**。（正在开发）


### 推送

- **推送规则**：推送规则 = 主播 × 内容 × 渠道 × 推送词。例如「阿梓 + 歌回 → QQ 群：阿梓唱歌速来」。多条规则同时命中时各自生效，但同一个渠道只推一次（取最高优先级）。
- **推送时机**：开播时推送、下播时推送、动态/微博更新时推送。可按规则单独配置。（画饼，待开发）
- **推送渠道**：Windows/macOS 系统通知、QQ 群/私聊（NapCat）。可按规则单独配置。
- **NapCat 托管**：自动维护 NapCat（QQ 机器人）的专属端口条目、进程看门狗挂了自动拉起。


### WebUI

- **时间表**：可视化展示每个主播的直播历史、分类结果、未来直播预告。
- **主播详情**：每个主播的直播状态、动态、微博。
- **控制面板**：所有设置在浏览器里完成。
- **DDTV**：直接播放直播画面，并同屏多开，或快速换台。（画饼，待开发）


### Agent 接口（正在开发）

- **MCP**：为本地 Agent 开放接口，使之可以读数据、改规则，让 DD-Claw 真正具备 Claw 能力。
- **MaiBot 插件**：当同一个 bot 账号同时使用 MaiBot 参与群聊时，靠 MaiBot 的 Agent 决策调用，并限制权限边界为本群自助。
- **QQ 直连**：当该 bot 只作为推送 bot 时，可以选择直接接收 NapCat 消息。通过斜杠指令快速响应，或依赖内置 Agent Loop 完成自然语言对话。
- **WebUI 对话框**：在控制面板里直接和 Agent 对话，改规则、查数据。

## 上手

Node.js 22 以上；QQ 推送需要 NapCat。

```bash
npm install
npm run build
node dist/index.js
```

首次启动后打开控制面板 <http://127.0.0.1:8787>（只监听本机），之后所有配置都在面板里完成：

1. **登录**：在「监听」卡片里扫码登录 B 站（关注列表 + 动态）和微博（可选）。不登录也能用，直播状态监听不依赖登录，但功能较少。
2. **加主播**：B 站登录后关注列表会自动同步，点头像一键加入监听；微博登录后可在主播卡片里追加微博号。
3. **QQ 推送**：在「NapCat」卡片填写路径和机器人 QQ 号；在「推送渠道」卡片添加 QQ 群/私聊渠道。
4. **定义分类规则**：在「分类规则」卡片新建分类，比如「歌回」——填关键词（唱、歌回）或分区（虚拟Singer），或者写一段 LLM 提示词描述这类直播的典型特征。规则可以拖拽排序决定优先级。
5. **定义推送规则**：在「推送规则」卡片新建规则，选分类（或「任意开播」）、勾选生效主播（不勾 = 全部）、选渠道、填推送词。规则可以拖拽排序决定优先级。

开发期用 `npm run dev`（改动自动重启）。常用验证命令：`npm run probe`（测一次开播状态接口）、`npm run probe-llm`（测 LLM 接入）、`npm run test-notify`（假消息走完整推送链路）。

### 数据存在哪 / 迁移

所有面板设置和历史数据都在项目目录里，换机器迁移带走这三样即可：

- **`data/dd-claw.db`**（含 `-wal`/`-shm` 伴生文件）——全部面板设置（监听名单、分类与推送规则、渠道、LLM provider 与 key、NapCat 与高级设置）+ 历史数据（直播场次时间轴、分类判定、动态/微博存档、推送日志）。
- **`cookies.json` / `weibo-cookies.json`**（项目根目录）——B 站 / 微博登录凭据。不带也行，到新机器上面板重新扫码即可。

可以不带：`config.json`（只剩面板端口等自举项，缺省自动用默认值）、`.env`（只剩数据库路径与日志级别，缺省即可）、`data/cache/`（通知图片缓存，自动重建）。

## 隐私与边界

- 全部数据只存在本地：设置与历史数据在 `data/dd-claw.db`，登录凭据在项目根的 `cookies.json` / `weibo-cookies.json`，不上传任何服务器；LLM 请求只发往你自己配置的接口地址。
- 对 B 站和微博**只读不写**：不发弹幕、不点赞、不评论，所有抓取走公开页面/接口加你自己导入的登录凭据。
- 扫码登录的 cookie 用于接口调用，绝不写入日志。

## 当前状态与已知限制（开发进度）

- LLM 分类管线已接通（提示词、多模态画面输入、失败回退、结果入库），但分类效果未经实测，仍待开发验证。
- LLM 的画面判断目前只能用封面/关键帧截图；「弹幕内容」类特征（比如提示词里写弹幕打 call 词）还没有输入来源，弹幕抓取是后续计划。
- 直播中途改标题不会触发重新分类；直播中抽查、预告时间表（从动态/微博提取时间）在路线图上。

更深入的架构设计见 `docs/design.md`，接口能力边界与踩坑记录见 `docs/boundaries.md`。
